# Kimi Paper

专门适配原生 Kimi Code 的 macOS 写作工作台：左侧保留 Kimi Web 自己的工作区、会话和模型界面，右侧独立浏览文档文件夹、划选翻译或发起细节修改。

[tex-mcp-web](https://github.com/MiiKiyoshi/tex-mcp-web) 提供 PDF 显示和选区能力。本仓库维护原生应用、持续 Kimi Web 会话、PDF 自动重新编译和 GitHub 协作。不是 Kimi 官方应用。

## 使用

双击已安装的 Kimi Paper。左侧直接使用 Kimi 原生侧栏：可以在同一目录新建多个会话，也可以让不同会话分别选择论文目录、数据目录或更上层的研究目录。应用不再提供第二套工作区选择器，也不会替你自动创建会话。

顶部选择右侧文档文件夹，点击阅读栏的“文件”浏览子目录、打开 PDF、Markdown、UTF-8 文本和图片；打开 LaTeX 主文件时显示编译后的 PDF。文件列表使用可收起的浮层，不长期挤占正文。Kimi 工作时仍可切换文档；只有发送批注的短暂交接和 Git 维护期间暂停切换。GitHub 的操作范围是顶部所选文件夹，面板同时显示完整路径。

左侧适合起草和大修改；右侧划选文字、写下要求后，会发送到当前 Kimi 会话，并明确携带源文件路径。独立 PDF 的批注会要求 Kimi 先查找并核对可编辑源稿，不默认修改另一篇论文。所有 Agent 空闲后，当前文本预览自动刷新，已绑定的 LaTeX 论文自动重新编译。编译失败不再让 Kimi 状态一直停在“忙碌”。详见 [使用说明](docs/使用说明.md)。

依赖本机已安装且登录有效的 Kimi Code；仅编译 LaTeX 需要 LaTeX 和 latexmk，普通文档文件夹无需 `.tex` 主文件。阅读翻译使用独立 API，支持 Qwen-MT。当前不支持 Word 内置编辑、扫描 PDF OCR 或仅凭 PDF 还原源稿；图片仅预览，其他格式可在 Finder 中打开。Markdown 支持基本标题、段落和列表，大文件降为源码显示，不执行 HTML 或加载远程资源。

## 从源码构建

已验证环境：Apple Silicon macOS、Swift 6.3.1、Python 3.12.13、Kimi Code 0.41.0、mcp 1.29.1。

需要 Apple Command Line Tools（或 Xcode）、[uv](https://docs.astral.sh/uv/)、Git，以及上述 Kimi / LaTeX 环境。

```bash
./scripts/build.sh
./scripts/check.sh
bash ./scripts/check-documents.sh
```

首次构建需要联网下载 Python 依赖及固定提交的 tex-mcp-web。Python 环境在仓库的 `.runtime/` 中创建；打包时将运行时复制进应用。构建不会替换个人应用程序文件夹里已安装的版本。重复构建会把旧产物保留在 `dist/previous-*`；成功构建后按备份目录创建时间只保留最近两份。构建与清理使用同一把锁；若备份正在使用、目录结构异常或检查失败，保留备份并提示未完成清理。此策略仅管理 `previous-*`，不会自动处理安装到其他位置时产生的备份。

`./scripts/build.sh --run` 会在构建后打开应用。若有完整 Xcode / XCTest 环境，还可以执行 `swift test`；只有 Command Line Tools 的已验证机器使用上述独立检查及实际应用流程测试。

## 仓库内容

- `Sources/`：原生窗口、双栏网页、Kimi API 和进程生命周期。
- `Resources/`：项目准备器、进程监督器、图标、应用元数据及上游虚构示例论文。
- `scripts/`：准备运行环境、构建、检查。
- `Tests/`：任务并发、隔离、取消、事务恢复与翻译请求的检查。
- `requirements.lock`：固定的 Python 依赖版本和上游 Git 提交。
- `licenses/` 与 [第三方来源](THIRD_PARTY_NOTICES.md)：来源及许可信息。

应用本身、Python 环境、真实论文、批注记录、Kimi 私有配置和登录凭据不应提交到源码仓库。应用更新暂由本地重新构建完成，没有自动更新服务。

## 当前验收状态

0.8 增加独立文档浏览、原生 PDF/文本划选和纯文档 Git 服务。Swift 独立检查覆盖忙碌时切换、旧视图/旧文件/过期选区拒发、并发发送、模型保留及文件读取边界；Python 全量 135 项回归通过。独立测试窗口已验证 Markdown 排版/划选、PDF 选区与页码、滚动保留浮窗、点击空白关闭、文件切换保持 Kimi 会话。原生新格式修改发送使用假 Kimi 客户端验证，未将其记为真实模型修改验收。正式 0.8.0 build 13 已安装；沿用原有钥匙串和阿里云 qwen-mt-flash，通过全新 Markdown 选区实测返回中文译文。安装状态和复验细节见开发计划。

0.6 将工作区控制完整交还给原生 Kimi Web。应用使用一个独立本地 Kimi 服务承载所有原生会话，允许同时运行同目录或不同目录的多个会话；启动时不附加自动批准或权限绕过参数。右侧批注在发送前同时核对会话世代和当前 PDF 版本，切换会话后的旧请求不会误发。右侧论文可以独立更换，不会重启 Kimi。

应用保留上一次编译成功的 PDF。Git 操作会先锁住左侧输入、确认所有 Agent 空闲并暂停 Kimi，完成后恢复原会话。打开论文只读取既有 `.tex-mcp-web.yaml`，不会为了启动而创建或重写项目配置。

自动检查使用虚构论文，Git 推拉使用本地模拟远端；不自动操作真实论文仓库。翻译回归使用模拟接口，不重新读取私人密钥。详细记录见 [开发计划](docs/开发计划.md)。

## 维护

目前按私有应用源码仓库整理，尚未决定对外公开发布或原生代码的开源许可。上游依赖遵守各自许可证。先在示例论文验证改动，再更新日常使用的安装版；更换 Kimi 或 tex-mcp-web 版本时应重新验证连接、批注、编译和退出清理。
