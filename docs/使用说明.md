# Kimi Paper 0.4 使用说明

## 打开或新建论文项目

打开 Kimi Paper，点击左上角项目名称，选择整个论文项目文件夹。正文、章节、参考文献库、图表与研究脚本都应放在这个项目内。已有 `main.tex` 会直接打开；其他主文件可通过选择器指定，包括子目录中的主文件。

新论文可以选择一个空文件夹，在随后主文件选择器中取消，默认以 `main.tex` 起草。左侧是原生 Kimi Code Web，默认 Kimi K3 256K；模型、思考强度、工具权限与会话均使用 Kimi 自己的控件。

## 从初稿到修改

1. 在左侧描述论文内容、提纲或修改要求。Kimi 在持续保留的草稿副本中工作，原生搜索、文件工具等仍可使用。
2. Kimi 完成修改后应用会生成 PDF 预览；也可以点击右上角「生成预览」。空项目的第一份 PDF 也在这里出现。
3. 在右侧划选文字，可以自动翻译或点击 Comment 写批注。默认发给左侧当前会话；勾选「先保存」后，可以连续添加，再点击「发送积攒批注」。
4. 「修改记录」中按时间选择版本，主窗口右侧会显示该版本 PDF。关闭面板可继续阅读全文。原始 AI 回复和修改原因保留在左侧会话；源码差异放在可选展开项。
5. 确认满意后，在该版本中点击「确认采纳到正式稿」。应用合并并编译检查，通过后才更新正式项目，同时保留本地版本。

应用重开会恢复项目草稿与会话。修改记录可以手动归档和恢复，已采纳版本可撤销。采纳只取冻结版本，不会把尚在变化的草稿直接写进正式稿。

## 项目文件、版本与合作

「项目文件」展示正式项目中纳入草稿与本地版本的内容；常见图片、文本和文献库可点击查看。配置、凭据、隐藏目录、运行缓存和不支持的文件会单独列明。文件类型和大小限制以实际面板为准；不要把大型原始数据集或登录资料放进论文资产中。

「版本与 GitHub」提供本地版本查看，以及建立仓库、选择文件暂存、提交、连接 GitHub、检查更新、拉取和推送。每项 Git 操作先展示范围，再由你确认。项目仓库与 Kimi Paper 应用源码仓库相互独立。

合作时建议每人使用自己的分支，在 GitHub 发起合并请求。应用不自动强推、不自动覆盖分叉历史。拉取或切换分支改变的是正式项目；持久草稿保留原状。需要接收合作方的最新稿件时，在修改记录中点击「从正式稿更新草稿」。此操作会先停止 Kimi、检查未冻结改动，并保留原草稿副本。冲突必须先处理，不能靠重复点击强行覆盖。

## 翻译

右侧划选翻译使用已配置的独立 API；「更多 → 翻译设置」可修改接口与模型。支持 `qwen-mt-flash`。译文仅用于阅读，不会自动写进论文。

密钥仍由系统钥匙串保管，成功读取后在当前应用进程内复用。更新应用或重启后可能需要首次系统授权；应用不会替你输入系统密码或降低钥匙串保护。

## 出错时

- **编译失败**：查看修改记录中的错误，把错误交给左侧同一会话修复。修复前不能采纳。
- **Kimi 请求等待权限**：在左侧原生界面判断并处理具体请求；应用不会自动批准任意命令。
- **合作改动冲突**：保留双方修改，先检查差异。不要手动替换整个正式项目。
- **连接中断**：通过更多菜单重新连接。已保存的会话和草稿不会因窗口关闭而主动清空。

当前支持本地 LaTeX 项目；不支持扫描 PDF OCR、Word 直接编辑，或仅给 PDF 就恢复全部源工程。
