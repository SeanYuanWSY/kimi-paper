# Kimi Paper 0.5 使用说明

## 日常只需要三个操作

1. 点击左上角的文件夹名称，选择 **Kimi 的研究工作区**。
2. 在左侧直接和 Kimi 对话，用它起草论文、改结构、分析项目数据或生成图表。
3. 在右侧阅读 PDF；划选文字并写下要求，当前 Kimi 会话会直接修改这一处。

顶部的「GitHub」用于查看项目状态、提交、拉取和推送。翻译、手动编译、重新连接和撤销最近修改收在「更多」菜单中。

## 选择正确的工作目录

研究工作区不必是 LaTeX 文件夹。它可以是更上层的真实项目目录，例如：

```text
my-research/
├── paper/main.tex
├── data/
├── figures/
└── analysis/
```

这时选择 `my-research/` 作为工作区，再选择 `paper/main.tex` 作为论文主文件。工作区可以同时包含：

- `main.tex`、章节文件和参考文献库；
- 图片、表格和绘图脚本；
- 这篇论文需要的数据与分析代码；
- 项目自己的 Git 仓库。

顶部会显示工作区的绝对路径，右侧显示论文主文件在工作区中的相对路径。Kimi 的会话绑定工作区，因此它能看到同一项目中的数据、脚本和图表。更换为论文主文件的上级目录时，只会改变 Kimi 的工作区，不要求重新移动或选择论文。

应用拒绝把用户主目录、系统目录、Kimi/Codex 配置目录或应用私有目录当作论文项目。

## 大修改与细节修改

左侧是原生 Kimi Code Web，适合从零起草、整体重写和连续讨论。模型、思考强度、工具权限和会话切换仍使用 Kimi 自己的控件，默认模型为 Kimi K3 256K。

右侧适合细节修改：

1. 在 PDF 中划选原文；
2. 点击批注入口，输入具体要求；
3. 点击「开始修改」；
4. 要求会发送到左侧当前会话，Kimi 直接修改原项目文件；
5. Kimi 结束后，应用自动重新编译并刷新 PDF。

编译失败时，右侧继续保留上一次成功的 PDF，并提示你让左侧 Kimi 修复错误。

## 本地恢复边界

应用在私有目录中保存最近一次 Kimi 修改前后的恢复点。「更多 → 撤销最近一次 Kimi 修改」会先检查当前文件没有冲突、验证撤销结果可以编译，再恢复源文件。

普通正文、文献、图片、数据、脚本和绘图文件会进入恢复范围。现有的隐藏配置、凭据、大于 50 MB 的单文件和符号链接可以被 Kimi 读取，但应用禁止 Kimi 改写它们，因为这些内容不适合自动复制到本地恢复点。

在应用关闭时发生的人工修改，以及 Git 拉取、新建分支或切换分支，会成为新的工作基线，并清除跨边界的「撤销最近修改」入口，避免误退回合作者的内容。

## GitHub 协作

「GitHub」面板提供：

- 查看当前分支和改动；
- 选择文件暂存并提交；
- 拉取、推送；
- 新建或切换分支；
- 设置远端仓库。

分支和远端设置收在面板的展开项中。Kimi 工作期间会暂时阻止 Git 工作区操作；拉取、新建或切换分支时，应用先暂停 Kimi，完成后建立新基线，再恢复同一个会话。应用不会自动强推、重写历史或替你解决冲突。

多人合作时，建议每个人使用自己的分支，在 GitHub 上通过 Pull Request 合并。提交前先检查文件范围，避免把 API 密钥、登录配置或大型原始数据上传到论文仓库。

## 翻译与其他设置

右侧划选翻译仍使用独立翻译 API，支持 `qwen-mt-flash`。译文只辅助阅读，不会写进论文。「更多 → 翻译设置」可以开关翻译、修改接口和模型；密钥由 macOS 钥匙串保存。

「更多」还提供重新编译 PDF、重新连接 Kimi、打开示例项目和使用帮助。旧版的隔离草稿、候选记录与采纳历史仍保存在应用私有状态中，0.5 默认界面不再展示这些复杂入口。

当前支持本地 LaTeX 项目；不支持 Word 直接编辑、扫描 PDF OCR，或仅凭 PDF 恢复完整源工程。
