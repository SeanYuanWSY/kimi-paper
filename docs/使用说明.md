# Kimi Paper

构建后的应用位于仓库的 `dist/Kimi Paper.app`，双击即可打开。也可以自行复制到个人「应用程序」文件夹（`~/Applications/`）。构建脚本不会自动替换已经安装的版本。

应用专门适配原生 Kimi Code。右侧阅读论文，左侧查看修改建议、本地版本和 GitHub 协作。所有正文修改都需要你确认采纳。

## 平时怎么用

1. 双击 Kimi Paper，恢复上次论文。
2. 在 PDF 划选文字，点 Comment 写要求；全文意见用 + Note。
3. 默认 Kimi K3 256K，可更换模型。普通润色选“直接修改”；需要搜索或工具选“深入处理”。
4. 立即提交可后台并行生成（最多 3 个）。也可勾选“先保存批注”，积攒后在左侧点“统一处理”，按顺序生成。
5. 点回原批注，查看对应建议；可“采纳写入”或追加意见再改一版。版本菜单保留历次建议，完整差异在左侧查看。
6. 采纳时检查冲突与编译，通过才写入并更新 PDF；也可撤销采纳。

批量任务共享整批批注及前序建议上下文，每处仍分别由你确认。普通模式由应用提供论文内容，Kimi 只返回建议，不调用文件或 Shell 工具。深入处理保留原生工具和具体权限请求，不会自动同意所有授权。超过普通入口内容上限时会提示切换深入处理。

失败或中断不自动重跑。退出时停止运行中的任务，已保存的建议重开仍在。历史 Codex 记录保留，不再提供新 Codex 执行入口。

## 本地版本与 GitHub 合作

每次采纳和撤销都会自动保存本地版本，在左侧「本地版本记录」查看实际写入差异。这些记录独立保存在应用数据目录，不改变论文 Git 分支，也不自动上传。

展开「GitHub 协作」后：

1. 没有仓库时，点击建立独立仓库。GitHub 的新建链接用于在网页创建仓库（建议私有），随后粘贴地址连接。
2. 勾选准备保存的文件，加入暂存，填写版本说明并提交。已有暂存内容会一并明确列出，不会被清空。尚未设置 Git 作者身份时，需先在常用 Git 工具中配置。
3. 与他人合作时，先检查远端更新并拉取，再新建自己的协作分支。完成修改后手动推送，在 GitHub 网页发起合并请求，由合作者审核。
4. 本地领先/落后数量基于最近一次检查；「刷新仓库状态」只读本地，「检查远端更新」才联网。

所有按钮先预览、再确认执行。拉取只允许快进；工作区未保存、双方分叉或存在冲突时会停止并提示，保留现有修改。没有自动 stash、reset、强推或后台推送。复杂冲突、LFS、子模块和历史修复交给外部 Git 工具；不能以拉取成功代替协作审核。

发布检查限制文件类型，并扫描待发布历史中的常见凭据格式；它不能判断论文是否涉及保密，也不能保证识别所有秘密。请核对仓库可见性和发布范围。论文仓库与本应用的源码仓库是两回事。

## 阅读翻译

在左侧 **修改任务 → 翻译设置** 填写完整 HTTPS Chat Completions 接口地址、模型名、目标语言，以及服务需要的 API 密钥，然后保存并测试。密钥保存在本机系统钥匙串，不进入源码仓库；更换接口地址时需要重新填写密钥。

默认使用 **划选后自动翻译**：在 PDF 中拖选一段文字，松开鼠标后，译文显示在选区旁的浮窗中；浮窗内可点“写批注”继续提出修改要求。点击空白处、按 Esc 或滚动论文可收起浮窗；顶部开关可暂时关闭自动划选翻译。译文只辅助阅读，不修改 LaTeX。重复段落使用缓存，失败可点“重试”。

如需整屏阅读辅助，可展开 **阅读翻译**，勾选 **滚动停下后自动翻译**；这是可选的独立入口，默认不展开顶部译文栏。

应用不附带翻译账号或付费额度；未配置时会显示设置提示。扫描 PDF 或无法可靠提取文字的页面不支持自动 OCR。

已实测千问 `qwen-mt-flash`，完整接口地址可填写 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`（北京地域）。模型名以 `qwen-mt-` 开头时，应用自动使用千问专用翻译参数；目标语言“简体中文”会映射为 `Chinese`。其他语言优先填写服务支持的英文全称。不同地域的密钥和接口必须对应；也可使用百炼控制台提供的业务空间专属地址。见[官方接口说明](https://help.aliyun.com/zh/model-studio/qwen-mt-api)。

## 打开自己的论文

点顶部 **打开论文**，选择 `main.tex` 等 LaTeX 主文件。有多个 `.tex` 文件时请选择真正的编译入口。

应用会在该论文目录添加自己的批注配置和项目 MCP 配置；已有 MCP 内容会保留，并在更新前生成权限为 0600 的备份。只有你提交修改任务才调用 Kimi。

现在支持本地 LaTeX 工程。只有 PDF 或 Word 文件时，不能直接按这套流程修改源稿。候选从干净副本完整编译，需要 latexmk 及对应的 LaTeX 编译器、参考文献工具与宏包；最终仍有未解析引用时不会采纳。复杂模板的自定义 latexmkrc 或 shell-escape 不会执行；已有 tex-mcp-web 配置会沿用。

## 常用操作

- **更多 → 打开示例论文**：用虚构论文尝试功能。
- **更多 → 刷新页面**：重新加载左右页面。
- **更多 → 重新连接**：重新启动论文服务并加载当前论文。
- **更多 → 在 Finder 中查看论文**：找到正文文件。
- 退出应用会停止它启动的服务。处理中退出会出现确认；论文与对话已保存的部分仍会保留。

本应用复用了 [Kimi Code](https://moonshotai.github.io/kimi-code/en/guides/web.html) 和 [tex-mcp-web](https://github.com/MiiKiyoshi/tex-mcp-web)，是为这台 Mac 制作的本地集成应用，非 Kimi 官方发布的独立产品。目前依赖这台 Mac 上已有的 Kimi Code 和 LaTeX 环境。

### 系统钥匙串授权

若出现“登录钥匙串密码”弹窗，输入的是钥匙串密码（通常与 Mac 登录密码一致），不是翻译 API 密钥。希望当前 App 后续读取时不再询问，可由本人选择“始终允许”。首次使用更新后的构建、重启或再次更新后仍可能需要系统授权。

翻译服务现在会在当前服务实例内复用成功读取的密钥，并绑定接口地址；改变接口、替换或移除密钥前清空内存引用。密钥不进入翻译结果磁盘缓存。此处理没有改变系统钥匙串权限或应用签名，不能保证跨更新永远不弹窗。
