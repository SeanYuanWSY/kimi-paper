# Kimi Paper 0.6 使用说明

## 日常只需要三个操作

1. 在左侧 Kimi 原生侧栏选择工作区并打开或新建会话。
2. 在左侧对话中做起草、结构调整、数据分析和整篇修改。
3. 在右侧阅读 PDF；划选文字并写下要求，把细节修改发送到当前会话。

顶部的「GitHub」用于查看论文项目状态、提交、拉取和推送。翻译、手动编译和重新连接位于「更多」菜单。

## Kimi 工作区与右侧论文彼此独立

应用不再提供额外的工作区选择器。左侧就是完整的原生 Kimi Web：

- 同一个目录可以新建多个会话，让多个 Agent 分别工作；
- 不同会话可以选择不同目录或不同层级；
- 一个会话可以选择包含 `paper/`、`data/`、`figures/` 和 `analysis/` 的上层研究目录；
- 模型、思考强度、权限提示、会话搜索与归档继续使用 Kimi 自己的界面。

右侧只绑定一篇论文的 LaTeX 主文件。点击论文栏的「更换…」选择另一份 `main.tex`。切换时只重开右侧论文服务，左侧 Kimi 进程、工作区和当前会话保持不变；Kimi 正在工作时该按钮会暂时停用，避免在文件变化过程中切换预览对象。

例如：

```text
my-research/                 ← 左侧某个 Kimi 会话可选择这里
├── paper/
│   ├── main.tex             ← 右侧论文绑定这里
│   ├── references.bib
│   └── figures/
├── data/
└── analysis/
```

另一个 Kimi 会话也可以直接选择 `my-research/data/`，或选择完全不同的项目。右侧仍保持当前论文。

## 大修改与细节修改

左侧适合直接告诉 Kimi：“根据这些实验结果重写 Results”“检查整个项目并补一版初稿”。Kimi 修改的是该会话拥有权限访问的真实文件。

右侧适合细节修改：

1. 在 PDF 中划选原文；
2. 输入要求并开始修改；
3. 应用记录当时的 Kimi 会话和 PDF 版本；
4. 要求发送到这条会话，并明确标出右侧论文根目录和主文件；
5. Kimi 结束后自动重新编译和刷新 PDF。

如果你在发送前切换了会话或 PDF 已更新，旧批注会被保留并要求重新确认，不会静默发给错误的 Agent。不同会话可以并行运行；同一会话的多条批注按顺序发送，避免互相覆盖。

## 权限与版本边界

应用启动官方 Kimi Web，不附加自动允许或绕过权限的参数。Kimi 能读取或修改哪些位置，以左侧会话选择的目录和 Kimi 自己显示的权限模式为准。

编译失败时，右侧保留上一次成功的 PDF，并提示你回到左侧修复。直接修改的版本控制以论文自己的 Git 仓库为准；提交前可在 GitHub 面板查看完整文件范围。打开论文不会自动创建或改写 `.tex-mcp-web.yaml`。

## GitHub 协作

「GitHub」面板作用于右侧绑定的论文项目，提供：

- 查看当前分支和完整改动；
- 选择文件暂存并提交；
- 拉取与推送；
- 新建或切换分支；
- 设置远端仓库。

执行 Git 操作时，应用先临时锁住左侧输入，确认所有 Kimi 会话空闲，再暂停本地 Kimi Web；操作完成后恢复原会话。应用不会自动强推、重写历史或替你解决冲突。

多人合作建议每个人使用自己的分支，通过 GitHub Pull Request 合并。提交前检查文件范围，避免上传 API 密钥、登录配置和大型原始数据。

## 翻译

右侧划选翻译使用独立 API，支持 `qwen-mt-flash`。译文只辅助阅读，不写进论文。「更多 → 翻译设置」可以开关翻译、修改接口和模型；密钥由 macOS 钥匙串保存。

当前支持本地 LaTeX 项目；不支持 Word 直接编辑、扫描 PDF OCR，或仅凭 PDF 恢复完整源工程。
