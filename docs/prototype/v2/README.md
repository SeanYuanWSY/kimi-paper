# 持续写作工作台 · 第二版交互样稿

日期：2026-09-06。入口 `/v2/`，与第一版独立，尚未替换安装版。所有论文内容、模型回复和译文都是明确标注的示例；没有连接 Kimi、Qwen、GitHub 或真实项目目录。

## 本轮用户决定

- 【转述】阅读与修改始终左右同屏；左侧需要完整的 Kimi 工作台，能选项目目录，从空项目起草，后续在同一会话内持续修改。
- 【转述】优先持续会话与上下文连贯性；不再默认给每条批注新开独立会话。多条批注可以放入当前会话统一处理。
- 【转述】保留整套项目文件、手动 GitHub、版本查看和划选自动翻译。前一版的分离阅读/修改导航不符合最新要求。
- 【判断】界面以项目、会话和论文三个对象组织。建议是会话产物，确认采纳后形成正式论文版本；项目文件、历史和同步操作不替换或清空当前会话。

## 调研与当前实现的差距

- 【已核实】[Kimi 会话文档](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/sessions.html) 说明会话持久化、按工作目录组织并可恢复。[Kimi Web 文档](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/web.html) 说明 Web 与 CLI 共享会话、配置和登录状态，支持会话管理、流式回复、权限交互与文件变更查看。
- 【已核实】[Kimi Server API](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html) 提供 REST/WebSocket 接口，并明确属于实验接口，集成应以本机版本 live schema 为准。本轮只查公开文档，未读取凭据或启动新 Kimi 服务；不能据此宣称本机原生嵌入与批注桥接已兼容。
- 【已核实】[Codex 官方介绍](https://openai.com/index/introducing-the-codex-app/) 描述项目组织的持续任务、任务内查看与评论改动、隔离 worktree。当前宿主也提供项目、任务、文件/浏览器侧栏接口。没有单独验证用户提到的 GPT Work PDF 批注行为，不据此声称其内部实现。
- 【已核实】[WorkBuddy 官方结果区文档](https://www.codebuddy.cn/docs/workbuddy/Results) 的搜索摘要明确右侧展示产出文件、代码改动和浏览器预览，支持不离开任务浏览工作空间文件。该页面正文抓取失败，未据此验证其 PDF 划选注释与会话内部协议。
- 【已核实】本地 `Resources/paper_prompt.py` 每次以 `-p` 启动无工具请求，并创建新的临时会话标识；`paper_engine.py` 提供论文文本、父建议和批次信息。因此“完全没有上下文”不准确，但它确实不是持续原生会话，和此次用户要求存在差距。

## 正式接入方向（尚未实施）

1. 优先复用原生 Kimi Web 工作台与持久会话，而非继续扩大无工具建议器。对本机 CLI 版本进行协议和嵌入验证后再决定 UI 桥接细节。
2. 应用持久记录项目根与所选原生会话标识。发送批注使用当前会话标识，不按批注新建；切项目明确切换所属会话，不串用上下文。
3. 批注包含选中文字、文件/PDF 版本、位置和要求；一次可发多条。主会话串行承接回合，运行时仍可读论文、攒批注。不要向同一会话同时提交互相竞争的生成请求；是否使用原生内部协作另行按能力验证。
4. 长上下文可能压缩。关键研究边界、已确认写作要求、采纳/拒绝决定需同步到项目记录；采纳后向同一会话回传实际文件结果。不能承诺“所有历史永远完整送入模型”。
5. 保留已确认的“正式稿写入需确认”。原生工具直接编辑与预览采纳必须协调：实现前验证可审阅草稿工作区/隔离副本及完整项目素材映射，不能只嵌入可任意改正式稿的 Web 页面后宣称具备写入保护。该步骤涉及核心架构与权限，实施前需要定点独立审查。
6. 从空项目起草也可生成章节、文献库和素材结构；严禁编造文献或实验结果。此样稿只演示起草入口与预览，不证明真实编译或研究写作能力。

## 边界

`localStorage` 只保存这份浏览器样稿的数据，不是 Kimi 原生会话。项目目录输入只是演示字段，不创建文件夹；正式 App 应使用 macOS 文件夹选择器。模型选择当前只有默认 K3 示例，原生模型目录未接入。排版是 HTML 示意，非实际 PDF。图片、表格、译文、回复皆为预设示例，建议生成不依据用户文本进行真实推理。编译失败、安装版权限弹窗与真实会话集成仍待后续解决。第一版文件保留在上级目录供对比。
